# 🎯 Universal Career Navigation Platform

> **A degree tells a student where they started. It should not decide where they can go.**

An AI-powered, interactive career navigation platform that helps students discover realistic career paths, understand eligibility constraints, identify skill gaps, and generate a personalized step-by-step roadmap from their current education to their target career.

# 1. 📌 Problem Statement

Students often know the career they want but do not know **how to reach it**.

Traditional career guidance is frequently:

- Generic rather than personalized
- Focused only on a student's current degree
- Difficult to visualize
- Not clear about eligibility requirements
- Weak at identifying the exact skills a student is missing
- Not connected to projects, certifications, internships, jobs, and long-term growth
- Static, even when a student's skills or goals change

A student may ask:

> "I am studying X. Can I become Y?"

But the real questions are:

- Is this career actually possible from my background?
- What additional qualification is required?
- Which skills do I already have?
- Which skills am I missing?
- What should I learn first?
- Which projects should I build?
- Which certifications are useful?
- When should I apply for internships?
- What entry-level roles should I target?
- What happens if I change my career goal halfway through?
- What is the long-term growth path?

The problem is therefore not simply **career discovery**.

It is **career navigation**.

# 2. 💡 Our Solution

## Universal Career Navigation Platform

Our platform converts a student's current profile into a **personalized, eligibility-aware, interactive career journey**.

Instead of treating a degree as a fixed career boundary, the platform treats the degree as an **input**.

### Core idea

```text
Student Background
       ↓
Skills + Interests + Strengths + Weaknesses
       ↓
AI Career Discovery
       ↓
Eligibility Check
       ↓
Skill Gap Analysis
       ↓
Career Goal
       ↓
Personalized AI Roadmap
       ↓
Learning
       ↓
Projects
       ↓
Certifications
       ↓
Internships
       ↓
Resume
       ↓
Interview
       ↓
Entry-Level Job
       ↓
Career Growth
```

The result is a visual career roadmap that explains **what to do, why to do it, and what comes next**.

# 3. 🚀 What Makes It Different?

## 3.1 Degree ≠ Career Limit

The platform is designed around a simple principle:

> **A student's degree is a starting point, not a career restriction.**

For example, a student's background can be considered alongside:

- Skills
- Interests
- Strengths
- Existing experience
- Additional qualifications
- Career goals

This allows the system to identify both direct and alternative pathways.

---

## 3.2 Career Navigation Instead of Career Recommendation

A normal career recommender may say:

> "You should become a Data Analyst."

Our platform goes further:

> "Here is why this career fits you, what you are missing, whether you are eligible, what to learn, which projects to build, when to seek internships, how to prepare for interviews, and how this can lead to long-term career growth."

---

## 3.3 Interactive n8n-Style Career Workflow

Instead of displaying a static list, the platform represents the career journey as an interactive node-based workflow.

Students can visually understand:

```text
INPUT → ANALYSIS → DECISION → ROADMAP → EXECUTION → CAREER
```

The workflow concept is inspired by node-based automation interfaces such as n8n.

Nodes can represent different stages of the student's career journey.

# 4. 🧩 Core Features

## 👤 1. Student Profile

Students can provide information such as:

- Education
- Degree / Course
- Branch / Subject
- Current year
- Skills
- Interests
- Strengths
- Weaknesses
- Career goal
- Available time

This becomes the input for the career intelligence system.

---

## 🔎 2. AI Career Discovery

The platform analyzes the student's profile and identifies suitable career options.

For each career, the system can provide:

- Career name
- Match reasoning
- Required skills
- Missing skills
- Qualification requirements
- Possible entry-level roles
- Eligibility level

---

## 🟢🟡🔴 3. Eligibility Checker

Career paths are categorized into understandable levels:

### 🟢 Direct

The student's background can directly support the career path.

### 🟡 Additional Requirements

The career may be possible, but additional qualifications, skills, certifications, or preparation may be required.

### 🔴 Restricted

The career requires a specific professional qualification or eligibility condition that cannot simply be substituted with general skills.

This helps prevent unrealistic career recommendations.

> Eligibility-sensitive information should be validated against authoritative sources before making high-stakes real-world decisions.

---

## 📊 4. Skill Gap Analysis

The platform compares:

```text
Current Skills
      +
Target Career Requirements
      =
Skill Gap
```

It identifies:

- Existing skills
- Missing skills
- Priority skills
- Suggested learning sequence

---

## 🎯 5. Career Goal

Students can select a target career and use it as the destination of their personalized roadmap.

---

The AI generates a structured career journey.

# 11. 🔐 Security & Configuration

Real credentials must never be committed to GitHub.

Environment variables should be used for secrets such as:

```env
GEMINI_API_KEY=your_api_key_here
DATABASE_URL=your_database_url_here
```

The repository should contain:

```text
.env.example
```

but **not real `.env` secrets**.

Recommended ignored files include:

```text
.env

!.env.example
node_modules/
dist/
build/
__pycache__/
```

Install:

- Node.js

---

```bash
git clone [ADD GITHUB REPOSITORY URL]

```

---

## Frontend

```bash
cd frontend
npm install
npm run dev
```

---

## Backend

Create and activate a virtual environment:

### Windows

```bash
python -m venv .venv
.venv\Scripts\activate
```

### macOS/Linux

```bash
python -m venv .venv
source .venv/bin/activate
```

Install dependencies:

```bash
pip install -r requirements.txt
```

Configure environment variables using `.env.example` as a reference.

For the deployed application, the database is hosted on **Neon PostgreSQL**. Set the Neon connection string through the server-side `DATABASE_URL` environment variable. Never commit the connection string to GitHub.

Start the backend using the project's configured FastAPI entry point.

### ☁️ Cloud Database — Neon

The application uses **Neon PostgreSQL** as its cloud-hosted database.

The FastAPI backend communicates with Neon for persistent application data:

```text
Frontend
   ↓
FastAPI API
   ↓
Neon PostgreSQL
```

The Neon connection string must remain server-side:

```env
DATABASE_URL=your_neon_postgresql_connection_string
```

**Security:**
- Never expose `DATABASE_URL` in frontend code.
- Never commit the Neon connection string to GitHub.
- Never put the real connection string in `.env.example`.
- Configure `DATABASE_URL` in the backend deployment platform.
- Keep `.env` ignored by Git.

The deployed frontend communicates with the deployed backend through environment-configured API URLs, while only the backend communicates with Neon.

# 18. ⚠️ Responsible AI

Career decisions can have significant consequences.

Therefore, the platform should distinguish between:

### AI-generated guidance

Used for:

- Career exploration
- Skill recommendations
- Roadmap generation
- Learning suggestions

and

### Authoritative information

Used for:

- Professional eligibility
- Licensing requirements
- Government requirements
- Regulated careers

For high-stakes eligibility decisions, users should verify requirements with the relevant official authority.

The platform is a **career navigation and decision-support tool**, not a replacement for official professional or institutional guidance.
